原始需求：帮我看下本地的这个都支持哪些接入方式

当前本地仓库（分支 feat/kiro-provider，提交 40c3289e）同时提供丰富的下游协议接入、多通道上游供应商接入、反向 WebSocket 中继以及可插拔的 C ABI 动态插件体系：

  1. 下游协议入口：覆盖 OpenAI（Chat / Completions / Responses HTTP & WS / Images / Audio / /openai/v1/videos*）、xAI 原生多媒体（/v1/videos*、/v1/tts）、Codex 直连与搜索（/v1/alpha/search、/backend-api/codex/*）、Codex Live WebRTC & 可用 Realtime 子集（不含 501 桩接口）、Anthropic Messages（/v1/messages）、Gemini（/v1beta/models*、/v1beta/interactions）与 Grok Shell UA 适配；外加管理 API /v8/management/*、mDNS 发现、TUI、Home 控制面、Go SDK 与同端口 Redis RESP 遥测队列。
  2. 上游接入方式：支持 7 家供应商共 9 个 CLI 交互式 OAuth 登录参数及 --siwc-bind、无交互账号导入（--vertex-import 与新增 --kiro-import）、管理 API 远程引导、8 组 api-keys 配置分组、AI Studio 反向 WebSocket 中继（/v1/ws）与 13 类内置上游执行器（不含辅助包装 oauth_scope）。
  3. 动态插件扩展：启用 plugins.enabled 后可通过 C ABI 动态库插件及插件商店扩展上下游能力。
