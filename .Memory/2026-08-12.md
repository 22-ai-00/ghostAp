# 2026-08-12 性能加固（阶段性收口）

## 已完成

- TaskScheduler 增加普通/系统队列独立容量（默认 1000/100）和终态历史上限（默认 5000）；准入在写入索引前原子完成，并持续清理空闲 chat/project/queue/running 索引，避免长期运行后无界增长。
- CardDelivery 建立可重试、幂等的 shutdown/drain 生命周期；registry 改为弱引用；普通编程自有 delivery 在成功、失败和 fallback 路径均回收。CardSession 在渲染前按不可变快照合并更新，并保护终态不被后续非终态覆盖。TimerScheduler 将慢回调移入有界执行器，关闭时统一排空或取消尚未开始的回调。
- 飞书卡片 action 的陈旧刷新和系统门禁提示改为 ACK 成功写回 WebSocket 后才提交的有界系统 follow-up；ACK 写入失败、handler 异常、关闭或容量不足时失败关闭且不做同步远程 I/O。相同 ACTIVE 项目且成员关系完整时仅刷新内存 LRU，跳过冗余快照重写/fsync。
- Workflow runtime 用 `AsyncLocalStorage` 建立词法 request collector lineage；并行 sibling race 互不取消，嵌套 descendant 仍继承父级取消边界。
- ACP 大型工具原文改为默认不捕获；仅 Workflow `AgentExecutor` 显式开启。该策略贯穿异步/同步会话、factory、compaction 和 failover，完整内容进入 Workflow 流时仍经过脱敏投影。

## 原因

- 限制长驻进程中的任务索引、线程/回调和原始工具载荷增长。
- 将昂贵卡片渲染及远程通知移出 ACK 热路径，并减少重复项目落盘。
- 修复并行 Workflow 的取消作用域串扰，同时保留全局取消与请求清理契约。
- 明确资源所有权和关闭栅栏，防止关闭返回后继续产生 I/O 或后台线程。

## 普通编程终态诊断与历史子代理对账

### 更改内容

- 修复终态错误卡无条件承诺“点击查看详情”但没有按钮的问题：只有绑定了诊断记录时才显示该提示与“查看详情”按钮；否则明确引导使用“查看状态”。
- 为普通编程失败、超时和异常终态注册与原始 chat/message 绑定的短期诊断 token；回调只返回经过脱敏和长度限制的结构化字段，不把原始工具输出或异常栈塞进卡片 action。
- 在 ACP 协作域新增最终 `list_agents` 权威证明跟踪。仅当任务正常 `end_turn`、没有未完成计划/外层工具/窗口耗尽，并且唯一异常是历史子代理记录未闭合、最终显式快照覆盖所有已观察子代理且均为终态时，将结果保持为“已完成”，同时显示黄色状态对账提醒和诊断入口。
- 新的 spawn/followup/activity 会立即使旧终态证明失效；未知或畸形身份/状态保持 fail-closed，真实未完成任务仍使用红色失败终态。
- 更新 `ux/programming-task-visibility.html`，增加“完成但需对账”和“真实未完成”两种终态预览，使绿/黄/红状态含义可直接审阅。

### 原因

- 原实现只写了折叠详情文案，`ProgrammingCardSession.fail()` 没有提供 `detail_action`，因此飞书端不存在可点击控件。
- 2026-08-12 的实例中，最终 `list_agents` 已确认 3 个子代理全部完成，但较早被中断的两代历史活动仍被结果分类器计作运行中；交付内容完整，属于状态对账告警而非任务失败。

### 验证

- 相关卡片、普通编程、ACP continuation 与 Codex rollout 扩展回归：185 passed。
- 新增诊断按钮绑定/回读、权威快照失效，以及最终快照/早期活动畸形证据 fail-closed 回归。
- Ruff 定向检查与 `git diff --check` 通过；UX 预览已使用 Chromium 渲染并人工检查。

### 后续风险

- 权威对账依赖后端发出结构化 `list_agents` 状态；协议缺失、未知状态或证据不完整时仍保守判为未完成，不从卡片显示或自然语言结论推断成功。
