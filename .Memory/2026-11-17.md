## 产品体验深度优化与后端原生 `/` 命令融合（4 批次重构 + 契约/路由收口）

### 背景与设计动因
对 GhostAP 全链路（飞书入口路由、`ProductCatalog`、`SystemHandler`、`ACP` 运行时、编程执行控制、卡片 2.0 渲染与诊断视图）进行设计审查后，聚焦四个影响交互自然度与安全一致性的短板完成系统性优化：
1. 各编程工具（AGY `/swarm`/`/boost`/`/plan`/`/compact`，Codex/Traex/Coco `/review`/`/review-branch`/`/mcp`/`/skills` 等）原生 `/` 命令过去无法自然发现与直达；部分命令会误被外层 prompt/bridge 包装覆盖 byte-0，或抢占 `system_fast` 队列。
2. 后端元数据在多个构建器/适配器/文档中重复枚举（早期仅列出 8 个模式，漏掉 `dsh`/`agy` 或缺少统一视觉主题），`switch_project` 切换项目会意外将保存的 `acp_tool_name` 重置为 Coco，锁/重试按钮缺少绑定 `chat_id` 的 v2 HMAC 与 Card 2.0 `behaviors`。
3. 长任务运行中编程卡片缺少直接停止按钮，自然语言 `停止` 被误路由为 `/exit`，缺乏不退出模式的 `/stop`、不丢工具/模型偏好的 `/clear`、全模式直通 `/sh`，以及不污染项目上下文的 `/ask <tool> <prompt>`；上下文历史也缺少改动文件列表与原始任务摘要。
4. `/status` 只呈零散文本或部分引擎，缺少统一的工作区驾驶舱视图（Git 分支、Direct 通道、Workflow/Deep/Spec 并行态、聊天/仓库锁与一键跳转按钮），同时缺乏统一 `/info` 入口。

## `/status` 完全无反应根因定位与全命令/卡片回调联动修复

### 问题原因
1. **缺少 `BaseHandler.reply_interactive_card`（直接导致 `/status`、`/cmds`、Smart 模式 `/info`、`/tools`、`/tools_status` 无任何回复）**:
   - `DiagnosticsHandler.show_unified_status`（`src/feishu/handlers/diagnostics.py`）与 `SystemHandler.show_tool_commands` / `show_tools_list` / `show_tools_status`（`src/feishu/handlers/system.py`）均调用了 `self.reply_interactive_card(...)`，但 `BaseHandler` 仅实现了 `reply_card` / `reply_text`，且单元测试通过 `diag.reply_interactive_card = MagicMock()` 屏蔽了该 `AttributeError`。
2. **`FeishuWSClient._process_message_async` 吞掉内部编程异常**:
   - `src/feishu/ws_client.py` 原仅捕获 `(RuntimeError, OSError, TimeoutError, TypeError, ValueError)`；上述 `AttributeError`（及 `LookupError`）直接逃逸到未 await 的调度器 `Future`，既不写入 `logs.log` 也不向用户回复错误提示。
3. **全命令与卡片回调逐项排查出的关联失效点**:
   - **项目查询方法名错误**：`SystemHandler.handle_show_tool_commands` 与 `handle_run_native_tool_command` 调用不存在的 `self.project_manager.get_project(project_id)`，在携带 `project_id` 点击卡片按钮时抛 `AttributeError`。
   - **`/clear`（`/reset`）未持久化**：`handle_clear_command` 检测 `save_projects()` 而非实际方法 `persist_project_context(target_project)`。
   - **`RETRY_COMMAND` 分发器属性名错误**：`src/feishu/action_registry.py` 读取 `client._dispatcher` 而非 `client._message_dispatcher`，导致通过重试按钮重放 `/wf`、`/deep`、`/spec` 或普通文本时回落进宿主机 Shell。
   - **`CONTINUE_DEV` 未发出 Ready 卡与部分按钮缺 Card 2.0 `behaviors`**：`handle_enter_acp_saved_selection` 未对无 `pending_prompt` 的入口传 `explicit_card=True`；`/tools`、`/tools_status`、`apply_compact_style`、Repo Lock 强解/确认卡、Deep 卡、LRU 驱逐通知卡与锁权限/超时卡缺少 Card JSON 2.0 `behaviors`（`callback`），且锁权限卡上的 `/status` 按钮未签名 `chat_id` v2 HMAC。
