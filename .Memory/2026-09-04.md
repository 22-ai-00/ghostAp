## Workflow 停止确认成为真实交付栅栏

### 影响与根因

- 非慢速全量测试暴露 `stop_workflow()` 的竞争窗口：运行时已收到停止信号，
  但执行 owner 的 `on_cancelled` 仍可能在“Workflow 任务已停止”回复后更新终态卡。
- 原实现只等待当时已进入的 `delivery_lock` 临界区，没有等待运行 owner 的
  取消终态投递与 finally 清理完成，因此确认消息并不代表后续写入已经静默。

### 修复

- 运行中停止在回复成功前有界等待 lifecycle owner 的 `done_event`；该事件只在
  取消终态回调、Bridge/Executor 清理和状态持久化之后设置。
- 等待耗尽时不再伪报成功：设置 stop delivery fence，阻止迟到的取消卡片写入，
  并明确回复停止未确认、项目保持停止中。
- 正常 `on_cancelled` 仍可在栅栏建立前投递完整取消终态，不影响既有取消结果卡。

### 验证

- Workflow 状态一致性、生命周期释放与多页交付合同：`52 passed`。
- 原竞态用例连续执行 20 次全部通过。
- 修改文件 Ruff 通过。

### 后续风险

- 停止静默等待上限为 5 秒；若底层 Bridge 无法在该时限内退出，用户会收到明确的
  “停止未确认”而不是成功消息，运行 owner 继续保持隔离以避免重叠执行。

## Main-Bot Warning deadline 前置耗尽不再丢失 Future 所有权

- 全量回归中 `test_delivery_deadline_keeps_inflight_transport_and_owned_resources`
  间歇失败；连续复跑确认固定 2 秒的测试 transport 等待会在重负载下自行结束，
  因此先将测试改为只由 `finally` 中的显式 release 解除阻塞。
- 去时钟化后进一步稳定复现生产根因：Future 已提交，但 deadline 可能在进入
  `Future.result()` 前耗尽；通用异常分支随后错误移除仍在运行的 Future，`close()`
  误判无 in-flight 后阻塞在 executor shutdown。
- 新增 retryable deadline 专用分支：Future 未完成时保留唯一所有权，只有已完成的
  retryable Future 才释放，避免关闭/恢复与仍在执行的传输重叠。

## ACP 模型激活、结论保真与错误卡契约收口

### 原始未提交改动的行为影响

- `/coco`、`/codex`、`/claude` 等显式入口统一先展示模型选择；项目已有保存配置时，
  普通任务继续自动选择并直接执行，不新增确认门。
- 激活从“模式标志推断会话存在”改为按 chat/project/topic 精确探测；缺失会话重新
  创建，支持的 direct session 可在线 setModel，其余用 identity-guarded replacement。
- 同坐标的多次选择采用 generation + fence，只有最新选择可提交项目配置、进入模式、
  更新终态卡或派发 pending prompt；`/exit`、卡片退出和项目切换共享同一生命周期边界。
- 子代理状态对账不再把内部 final_answer 或 `PromptResult.text` 覆盖到主任务结论；
  对账前冻结主 Agent 文本，后续真实 implementation continuation 可再次更新结论。
- 编程卡、模式初始化卡和错误卡增加固定通知摘要；错误详情仅在含 live chat 绑定时
  展示，避免空按钮和转发卡片跨群读取诊断。

### 审阅中补齐的正确性问题

- 在线 setModel 或新会话已生效、但项目配置提交失败时，精确退休已变更的 session，
  防止运行模型与持久化模型分叉。
- `/exit` 项目状态持久化失败时，不再宣称“会话已保存”；当前进程退出到 SMART，
  同时明确提示重启后可能恢复旧模式。
- activation 锁纳入正式 lock-order 层级并更新 ADR；状态 owner 终态后清理 generation
  与 fence 表，避免长期运行按 chat/project/topic 无界增长。
- CardEvent 与 SystemBuilder 都要求 chat-bound diagnostic action；仅有 origin/request/
  trace 或裸 token 不再渲染可重放的诊断按钮。
