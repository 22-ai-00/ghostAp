## Codex Goal 超时生命周期修复

### 事故时间线（UTC）

- `02:09:05.786`：GhostAP 的普通编程主执行窗口到达原始绝对 deadline，主 provider turn 超时，进入安全收尾路径。
- `02:11:49.307`：收尾 prompt 完成；此时 Codex provider Goal 仍存活，但旧实现没有消费 `_meta.codex.goal` 控制面事实。
- `02:11:49.311`：provider 在 4 ms 后自行启动下一轮 Goal turn，证明“当前 turn 已结束”不等于“Goal/session 已静止”。
- `02:11:49.365`：GhostAP 在收尾完成 58 ms 后退休会话。
- provider 新 turn 启动 103 ms 后才被终止；该尾部扩张发生在 GhostAP 已进入收尾/退休窗口之后。

### 根因

- GhostAP 忽略了官方 Codex adapter 通过 `_meta.codex.goal` 和 thread status 提供的 Goal 控制面元数据，只观察当前 ACP turn 的完成。
- turn 生命周期与 session/Goal 生命周期被混为一谈：当前 turn 结束或被取消后，provider-owned Goal 仍可继续排程下一 turn；旧收尾逻辑因此在未先暂停 Goal 的情况下继续发送 finalization prompt，并把执行窗口耗尽后的不完整结果呈现成普通未完成。

### 修复

- 新增冻结、类型化的 `ACPGoalInfo`/`ACPSessionInfo` 与 generation/transport-fenced Goal tracker；严格解析可信元数据，未知或畸形状态默认拒绝，不从渲染事件或静默推断生命周期。
- collector 的所有权扩展为整个 provider-owned Goal turn 集合：主 prompt、Goal 自行续起的 turn 与尾部 drain 共用同一收集器和 prompt 级图片预算，直到可信状态证明静止。
- 取消与 finalization 在发送 turn cancel/收尾 prompt 前，先在原预算内检查并暂停活跃 Goal；暂停失败、恢复提交不确定或强制快照竞态都会 force-dead 并退休精确会话，不把身份分裂会话重新放回池中。
- completion guard 对 active/paused/blocked/missing/unknown Goal 以及未决嵌套 child snapshot 均 fail-closed；只接受权威终态，不推断 child success，且观察到 provider Goal 后不再合成 GhostAP continuation。
- `entered_finalization` 跨 turn 保真，streaming 与 non-streaming 路径都明确报告“执行窗口已耗尽”；只有可信 `goal.status == "paused"` 才声明 Codex Goal 已确认暂停。

### 保持不变的安全不变量

- 所有主执行、Goal 静止等待、暂停和 finalization 共用原始绝对 deadline；修复没有重置或延长用户任务的总执行窗口。
- cancel、pause、drain 与同步桥接继续有界；Goal pause 使用带非空诊断动作的 `safe_wait_for`，不引入裸 `asyncio.wait_for`。
- 不确定 resume/load、暂停失败或生命周期竞态继续 force-dead 并退休精确 session；不会回退成貌似干净但身份不确定的新会话。
- 未决 outer tool 或任一 nested child 未获权威 completed/failed/cancelled 快照前，不推断 child success，也不把 Run 误判完成。

## 独立终审：同步取消失败收口

- 补齐同步 prompt 超时的双失败边界：当 Goal pause 与 turn cancel 同时失败并形成 `ExceptionGroup` 时，同步适配器记录完整取消异常链、取消本地 prompt future、force-dead 精确 wrapper，随后继续抛出原始 prompt `TimeoutError`，使 finalization 回调和精确 session 退休路径仍可到达。
- `SyncACPSession.cancel(wait=True)` 等待超时时，在返回未确认前取消 pending future 并 force-dead wrapper；`ACPSession.cancel()` 在 Goal pause 收到外部任务取消时立即传播，不再把 `CancelledError` 当作普通 pause 失败后继续发送 turn cancel，确保 deadline 后不会继续外呼。普通 pause 失败仍会尝试 turn cancel，并保留双失败原因。
- 严格 TDD 证据：首轮选择器先得到 `2 failed`（pending future 未取消、双失败 `ExceptionGroup` 逃逸），最小修复后为 `2 passed`；终审 follow-up 的真实后台 loop/真实 `ACPSession` 选择器先得到 `1 failed`（deadline 后仍调用 turn cancel），修复后为 `1 passed`。cancel 生命周期选择器为 `9 passed, 116 deselected`；`test_acp_sync_adapter.py`、`test_acp_session_event_fence.py`、`test_acp_prompt_finalization.py` 完整回归为 `125 passed`，保留 2 个既有 `lark_channel` Python 3.13 deprecation warnings；变更文件 Ruff 与 `git diff --check` 均通过。
- 最终独立复审确认 Critical/Important/Minor 均为零；双失败保留原始 timeout 与双因诊断，外部取消在 turn cancel 前传播，历史 task report、用户 `2026-08-05` 编辑和文档噪音边界均保持干净。
