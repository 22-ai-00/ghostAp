## 模型选择卡：为什么有些机器是按钮、有些是下拉框

### 直接分流条件

- `src/card/builders/system.py` 构建模型卡时计算
  `has_dimensions = bool(state.profiles or state.efforts)`：
  - 为真 → 渲染 3 个 `select_static` 下拉框（模型 / profile / reasoning effort）；
  - 为假 → 每个模型渲染一个 button，外加"使用默认"按钮。
- `profiles/efforts` 来自 `ACPModelOption.selection_variants`
  （`src/acp/options.py`）：只有 CLI/ACP 真的声明了可选变体时才非空。

### 各后端差异

- `codex` / `dsh`：逐模型探测 `reasoning_effort`，探测成功才有下拉。
- `traex`：读本机 `~/.trae/cli/models_cache.json`，恒至少合成 `standard` profile，
  因此基本总是下拉。
- `claude` / `gemini` / `grok` / `aiden` / `coco`：扁平映射，没有变体，永远按钮。
- 注意 CLI 形态的 `claude`（本机 shell 桥接）不走 ACP 发现：
  `fetch_acp_models` 对 CLI 后端直接 `_fallback()`。

### 机器间不一致的 7 个来源

1. CLI 是否安装 / 登录 / 版本差异；
2. 逐模型探测超时（`acp_model_probe_timeout` 默认 15s），慢机器探测失败→按钮；
3. traex 本机缓存文件 `~/.trae/cli/models_cache.json` 是否存在与内容；
4. ACP 能力声明差异（如 dsh 的 `@dsh-enhanced/acp` 插件版本）；
5. 内存缓存（正结果 1800s、负结果 300s，键为 `(tool, cwd)`；codex 同样 1800s）；
6. checker/slug 上的 `@lru_cache`：刷新卡片不会清，必须重启进程；
7. `build_clean_env` 造成的 HOME / PATH / 网络环境差异，导致探测结果不同。

## 新增隐藏命令 `/claude-w`（本地 claude-w CLI 桥接）

- 需求：与 `/claude` 完全同构（本地 shell CLI 桥接，per-prompt `claude -p`
  子进程 + `--resume`），但可执行文件名是 `claude-w`；命令必须隐藏——不进飞书
  斜杠自动补全、不进 `/tools` 与雇人发现，手打 `/claude-w` 才触发。
- 命名：对外 `/claude-w`、二进制 `claude-w`；内部标识统一 `claude_w`
  （InteractionMode 值、provider/tool、handler mode_key、intent、ctx 字段）。
- 主要改动（提交 `ad5d65cb`）：
  - `agent_session/backend_resolver.py`：CLI 后端集合与 agent↔binary 双向映射的
    SSOT（`claude_w ↔ claude-w`，未知二进制回退 `claude`）；factory 与
    startup_utils 的 CLI 分支统一按映射构造 `ClaudeCLIConfig`，`claude` 路径保持
    原调用签名不变（锁定既有测试契约）。
  - `mode/manager.py`：`InteractionMode.CLAUDE_W` + `enter/is_claude_w_mode`，
    `PROGRAMMING_MODES` 自动投影驱动 dispatcher 白名单路由
    （`ENTER_CLAUDE_W` / `CLAUDE_W_MESSAGE`，退出复用通用 `EXIT_MODE`）。
  - `acp/providers`：注册 `claude_w` provider（resolve checker 校验 PATH 中的
    `claude-w`），模型名透传不规范化；`acp/helper.py` 与 system handler 的
    `/tools` 列表显式隐藏它。
  - `product_catalog`：`/claude-w` action `slash_discoverable=False`，
    resolve 不过滤所以手打可解析（先例 `/spec_export`）。
  - `ClaudeWModeHandler` 继承 `ClaudeModeHandler`（复用 `_uses_claude_cli()`），
    ws_client 增加 manager/timeout/handler 接线；intent_recognizer 加精确斜杠与
    模式 fallback，刻意不加中文关键词与 smart 默认映射；project context 增加
    `claude_w` 模式字段与会话快照持久化；模型卡两处 1M 特判同步覆盖。
- 验证：新增 `tests/test_claude_w_bridge.py` 12 项回归（映射、factory 二进制选择、
  retry starter、快照 agent_type、模式/intent/handler、项目快照往返、隐藏性、
  provider 注册与工具列表隐藏、system 斜杠谓词）；同步 4 个既有测试夹具的新必填
  `claude_w_manager`/handler 字段。
