# 2026-11-28 — AGY Orchestrator 统一入口与 Planner/Executor 模型限定及交互优化

## 调研发现（`agy 1.5.18` 实测）

- 通过本机 `agy 1.5.18`（`/model` 交互、二进制 `orchestrator-model-roles` 策略、`agy acp` 与 `agy --settings`）确认：
  - `Orchestrator` 是 AGY 独有的单一行模式入口（而非在模型选择器中并列展示 3 条 `gemini-pro-orchestrator*` 预设），其下包含严格限定的 4 个选择维度：
    - **Planner 模型（4 种限定）**：`gemini-4-neon`、`gemini-4-carbon`（默认）、`gemini-4-argon`、`claude-opus-5-5`。
    - **Planner Effort**：所选 Planner 基础模型支持的实时档位（`low`/`medium`/`high`；`gemini-4-neon` 含 `xhigh`），当 `Executor == gemini-4-hydrogen` 且存在对应原生预设时额外提供 `default`（原生 ACP 预设，支持 `/swarm`）。
    - **Executor 模型（3 种限定）**：`gemini-4-hydrogen`（默认）、`gemini-4-neon`、`claude-sonnet-5-5`。
    - **Executor Effort**：所选 Executor 基础模型支持的实时档位（`low`/`medium`/`high`；`gemini-4-hydrogen`/`gemini-4-neon` 含 `xhigh`）。
  - 其余模型（如 `gpt-oss-120b-medium`、`gemini-3.8-flash`、`gemini-4-hydrogen` 作为 Planner、`gemini-4-carbon`/`claude-opus-5-5` 作为 Executor）均不可用于 Orchestrator 角色。

## 改动摘要

1. **统一入口与严格角色白名单校验（`src/acp/agy_selection.py`、`src/card/render/model_cascade.py`、`src/workflow_engine/tool_registry.py`、`docs/agy_acp_integration.md`）**
   - 新增 `AGY_ORCHESTRATOR_MODE_ID`、`AGY_ORCHESTRATOR_PLANNER_MODELS`（4 种）、`AGY_ORCHESTRATOR_EXECUTOR_MODELS`（3 种）、`AGY_PLANNER_NATIVE_ORCHESTRATOR_IDS` 及收敛/映射/展示标签辅助函数（`collapse_agy_orchestrator_group_names`、`canonical_agy_model_group`、`resolve_native_orchestrator_preset`、`format_agy_group_option_label`、`format_agy_role_option_label`、`format_agy_orchestrator_summary`）。
   - `compose_agy_orchestrator_selection`、`parse_agy_model_selection`、`is_valid_agy_catalog_selection` 与 `validate_agent_binding_spec` 严格 fail-closed 拦截越界角色模型；`normalize_agy_model_input` 兼容 `orchestrator` / `orchestrator/<rest>` 简写。
   - `AGYOrchestratorCascadeState` 新增 `planner_model_names` 与 `executor_model_names`；`resolve_agy_orchestrator_cascade` 修复裸原生预设（如 `gemini-pro-orchestrator`）回显保留 `default`、并在新开 `/agy` 默认展示 Carbon `high` → Hydrogen `high`。

2. **飞书交互卡片 2×2 紧凑布局与预览（`src/card/ui_text.py`、`src/card/builders/{system,tool_cockpit,workflow}.py`、`ux/acp-model-cascade.html`）**
   - `/agy`、`/model`、`/settings` 顶部 `model_group` 将 `gemini-pro-orchestrator*` 收拢为单一 `🪐 Orchestrator（双阶段规划+执行）` 入口，并为 AGY 模型增加可读展示名称。
   - 4 个 Orchestrator 下拉控件采用 2×2 `column_set` 并排配对（Row 1 `Planner 模型 + Effort`，Row 2 `Executor 模型 + Effort`，列宽比 `3:2`，`select_static` 不设 `width`）并附带单行组合摘要；修复 `workflow.py` `_extract_current_base_model` 对 3 段式 Orchestrator 选值的基模解析。
   - 更新 `ux/acp-model-cascade.html` Case 4 交互原型（含桌面端 `1280×1400` 与移动端 `500×1300` 响应式单栏截图布局修复与目检）。

3. **回调校验、一键升档与命令对齐（`src/feishu/handlers/{acp_activation,tool_cockpit}.py`）**
   - `/agy` 与 `/settings` 回调分别按 `planner_model_names` / `executor_model_names` 独立校验；当从 `default` 原生预设直接点击 `Executor Effort` 为非 `default` 档位时自动将 `Planner Effort` 升为 `high`，无需额外两步操作；优化 `/model list` 展示与 `/effort default` 原生预设回切。
