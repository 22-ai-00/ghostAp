# 2026-08-20

## 服务内同步重启只停不启修复

### 现场根因

- `logs.log` 中 2026-08-19 16:09:43 的失败轮只有 `[RESTART] stop begin`，随后主进程
  收到 SIGTERM 并在回调未排空时继续关闭；日志里既没有远程 worker 的
  `scheduled/script begin`，也没有停止降级、依赖检查或 `start begin`。服务一直中断到
  2026-08-20 01:19 从外部手工启动。
- 前后成功的机器人重启都先由 generation-gated worker 脱离服务进程树，再运行同步
  stop/start。失败轮则由 ACP 任务直接执行 `./restart.sh restart`；负责重新拉起服务的
  脚本仍是服务进程树的后代，服务关闭 ACP/回调进程树时把该脚本一并终止，形成
  “stop 已执行、start 永远没有执行”的自杀式重启。
- 02:17 的后续手工重启虽然优雅停机超时并升级为强制终止，但脚本来自服务进程树
  外部，仍在 10 秒内完成 readiness，排除了 Python 新代码或依赖无法启动的可能。

### 修复

- `restart.sh` 在同步 `restart` 入口沿 PPID 链识别调用方是否属于当前 checkout 的
  GhostAP 服务进程树。服务内请求不再先停止父服务，而是自动转交现有的脱离会话、
  generation-gated 安全重启 worker。
- 外部终端调用继续保持原同步 stop/start 语义，并保留“强制停止后仍尝试启动、最终
  返回降级状态”的既有合同。

### 验证

- `uv run python -m pytest tests/test_restart_script.py -q`：35 passed。
- 新增真实父进程 ancestry 探测、服务内委派前不得 stop，以及外部同步 restart 行为
  不变的回归测试。
- `bash -n restart.sh` 与 `git diff --check` 通过。

### 风险

- ancestry 判断依赖 Linux/macOS 均提供的 `ps -p <pid> -o ppid=`；若调用进程已被
  主动 daemonize 并脱离父链，它也不会随服务 ACP 清理被杀，因此可安全走外部同步
  路径。

## 删除 GhostAP 叠加执行安全层

### 更改与原因

- 用户把 GhostAP 定位为 Codex、Claude、Grok 等编程后端的远程入口，要求执行权限
  由后端自身负责，不再让 GhostAP 的第二套安全策略拒绝或改变后端请求。
- 用 `CommandExecutor` 取代 `src/sandbox/`：Shell 与 ACP terminal 直接继承宿主环境并
  运行命令，只保留超时、输出容量和非交互 pager 处理；删除命令黑白名单、风险模式、
  Shell 访问模式和相关配置。
- ACP 删除 tool filter、personal trust、auto-approve 分支和 GhostAP 命令风险判断；权限
  回调选择 provider 提供的 allowance，Codex 新会话请求 `agent-full-access`。文件和
  terminal cwd 不再局限于 session root。
- Claude CLI 与 Employee Channel 直接启动，不再使用 Bubblewrap、Seatbelt、Python
  isolated mode、attestation、ptrace/core-dump 包装或凭据环境正向列表；Employee 继承
  完整父进程环境。保留飞书身份、凭据文件完整性和 Journal/Effect 持久化合同。
- 删除 Autonomous `ActionMatrix` 及其动作/风险授权模型和 UI/诊断入口；保留管理员、
  tenant、群组/项目绑定等入口身份边界，避免把“谁可以操作服务”误删成“后端如何执行”。
- Workflow 取消 Node `vm`、禁止 import/`fs`/`process`/网络/子进程检查和环境裁剪；生成
  脚本作为临时 `.mjs` 在普通 Node 宿主中加载，Agent Pool 冻结绑定仍作为工作流产品
  合同。新增真实 Node 回归证明相对 import、`node:fs`、宿主环境和文件写入均可用，且
  `console.log` 不污染 JSON-RPC stdout。
- 删除 `PROJECT_ALLOWED_ROOTS` 和 `/cd` 范围判断；任意现存宿主目录均可选。移除旧
  sandbox/security 配置、启动探测、状态提示、测试和文档表述；历史 ADR/计划明确标注
  已被 2026-08-20 决策取代。
- 为旧 Journal frame 仅保留 `security_profile` 字段读取兼容并立即丢弃该值；新领域对象
  和派发绑定不再产生或执行该字段。

### 后续风险

- 这是有意的高权限产品变化：任何通过现有飞书入口身份边界进入的 Shell/编程任务，
  以及被选中的 provider/Workflow/Employee，都可使用 GhostAP 服务账号拥有的宿主机
  权限和环境。部署方应依赖后端自身权限模型与操作系统账号隔离，而不是旧 GhostAP
  配置。
- 旧 `SANDBOX_*`、`ACP_AUTO_APPROVE_TOOLS`、`ACP_TRUSTED_PERSONAL_*`、
  `CLAUDE_SKIP_PERMISSIONS` 和 `PROJECT_ALLOWED_ROOTS` 环境变量会被 Pydantic 的
  `extra=ignore` 忽略，不再影响运行行为。
