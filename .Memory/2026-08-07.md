## Codex Luna 节流配置

### 更改

- 保留用户级 `~/.codex/config.toml` 的 `gpt-5.6-sol`、`high` 和 `service_tier = "default"`，没有为照搬文章而提高主代理推理档位或启用 Fast。
- 在 `[agents]` 中设置 `max_concurrent_threads_per_session = 1`，限制单会话同时运行的子代理线程，避免并发重复消耗。
- 新增用户级 `~/.codex/agents/luna-worker.toml`：agent 名称为 `luna_worker`，模型为 `gpt-5.6-luna`，推理档位按用户要求设为 `max`。职责限定为边界明确、可独立验收的搜索、定点修改、目标测试和规则化重复工作；通过子配置禁用嵌套子代理。
- 未创建文章建议的 ChatGPT Pro 浏览器协作 Skill。当前官方手册不能保证这种路径绕开 Codex 用量，而且自动传递仓库内容会扩大数据暴露与提示注入边界。

### 原因

- 官方手册确认 GPT-5.6 Fast 为 1.5 倍速度、2.5 倍 Standard 信用消耗；现有 `service_tier = "default"` 已满足节流目标。
- 本机模型目录确认 Luna 支持 `max`；用户明确选择最高单代理推理档位，以更高单任务消耗换取窄任务中的推理深度。并发和职责边界继续承担总消耗约束。
- 主代理继续负责架构、跨模块取舍、安全/性能判断、集成和最终验收；worker 的描述与开发指令承担路由边界，无需增加始终加载的全局 `AGENTS.md`。

- `codex --strict-config --version` 通过，版本为 `codex-cli 0.146.0`。
- `codex debug models --bundled` 确认 `gpt-5.6-luna` 可用，并支持配置的 `max` 档位。
- 用户配置和 agent 文件权限分别为 `0600`，agents 目录为 `0700`；落盘内容与已审候选逐字节一致。
- 正常用户权限与真实 PTY 下执行 `codex --strict-config doctor --summary --no-color --ascii`：17 项通过、0 项失败，配置、认证、SQLite、WebSocket、HTTP 可达性和 app-server 均正常。

## TUI2ACP 后端与测试清退

### 更改

- 从当前产品面纵向删除 TUI2ACP：公开 Slash 命令及别名、Direct lane 投影、SystemHandler 命令与自动安装、卡片 action/adapter/custom-command UI、Router/WS manager/handler 装配、模式枚举和项目快照字段全部移除。
- 删除 ACP 传输层的 `tui2acp_<adapter>` 解析、外部 adapter 目录发现、专属 prompt-tail 时序，以及 `restart.sh` 中的 npm 包变量、全局安装函数和启动预热调用；保留通用 provider resolver、ACP 会话和 Codex ACP 预热。
- 当前 README 与执行通道 UX 收敛为仍支持的六个 Direct 后端。日期方案文档和 `.Memory` 中的旧记录继续作为历史证据，不参与当前运行或测试。
- 将原专名测试模块迁移为 `tests/test_programming_response.py`，改用真实 `ClaudeModeHandler` 构造，保留 continuation、finalization、Channel/card、delivery fallback 与 transcript 保真覆盖；仅删除两个 TUI2ACP 专属终态清理/对照用例，并清除共享 fixture、命令目录、路由、卡片和 restart 测试中的退役引用。
- 为通用 `acp_tool_name` 增加 provider 注册存在性校验：旧快照或运行期项目对象携带未知工具时清空工具与 stale model，再按当前有效模式或 Coco 回退；不保留任何 TUI2ACP 专属迁移 shim，也不以 provider 当前可用性误判已注册工具。
- 清理 pytest、mypy 与 Python bytecode 中包含退役符号或旧测试节点的生成缓存；没有添加负向墓碑测试。

### 原因

- TUI2ACP 是旁路 ToolRegistry 的独立 npm CLI 链路，拥有重复安装、专属状态和传输特判；用户要求完整删除其逻辑和测试，不能只隐藏 `/tui2acp` 入口。
- 原专名测试文件的大多数用例实际保护通用编程响应生命周期，整文件删除会造成无关覆盖损失，因此采用中性化迁移。
- 旧项目快照仍可能在通用 `acp_tool_name` 中保存已退役或未知值；用现有 provider registry 做通用过滤，可避免 `/model` 重新展示无效工具，同时不把退役名称固化为兼容代码。

### 验证

- 删除前基线：相关 catalog、Slash、WS、ACP、编程响应和 restart 测试 `208 passed`、`14 subtests passed`。
- 迁移后直接影响面：`750 passed`、`12 subtests passed`；文档噪声与 `/model` 修正精确复跑 `47 passed`。
- changed-file Ruff 全部通过；`uv run python -m src.main --validate` 通过；`scripts/test_inventory.py tests/` 统计 680 个测试文件、11123 个测试函数。
- 活跃源码、测试、脚本、README、AGENTS、配置清单、UX，以及 pytest/mypy/ruff/bytecode 缓存均通过大小写、分隔符、宽松 TUI↔ACP 内容扫描与文件名扫描，零残留；`git diff --check` 通过。
- 非慢速套件：`12369 passed, 1 skipped, 114 deselected, 57 subtests passed`。
- 包含 slow 的完整套件：`12483 passed, 1 skipped, 57 subtests passed`，仅有两条既有 `lark_channel` Python 3.13 deprecation warning。
- 生产清退、测试迁移和最终完整 diff 均经过独立审查；最终审查 Critical/Important/Minor 均为 0，判定可合入。

### 后续风险

- 历史 `.Memory` 和带日期方案文档仍会命中旧名称，这是有意保留的历史事实，不代表能力仍可调用。

## ACP 子代理终态误判修复

### 根因

- `logs.log` 的失败收口显示 `stop_reason=end_turn`、`pending_plan_entries=0`，但 `incomplete_tool_calls=1`；CardKit 更新均为 HTTP 200，聊天锁也正常释放，因此不是卡片投递、锁或重启失败。
- 对应 Codex rollout 中，评审子代理已经发送最终答案并结束；父代理最后一次 `wait_agent` 却先被普通 `MESSAGE` 唤醒，返回的仍是旧 `running` 快照，之后没有再次 `list_agents`/`wait_agent` 获取终态。
- 完成判定按历史外层 tool call 独立计数，既不会按稳定 child source 合并生命周期，也不会在“仅剩子代理状态未决”时做一次状态对账。因此自然 `end_turn` 携带旧 `running` 证据时默认拒绝并最终显示失败。

### 更改

- 新增严格的子代理生命周期归并器：按稳定 source 折叠状态，保持终态抵抗被动旧快照，同时以语义调用分槽保留 follow-up、新调用和跨轮时序；同 ID 的普通工具更新仍保持既有覆盖语义。
- ACP 元数据解析改为严格、不可字符串强转；无效 namespace/container/tool/source/activity/receiver/state 都留下耐久 malformed 证据。非空 `codex.collaboration` 缺失必需 `tool` 也默认拒绝，后续干净快照不能擦除歧义。
- 完成判定区分外层工具未完成与子代理生命周期未决，并输出仅含 allowlist 状态/种类/计数的脱敏诊断，不记录 thread ID、prompt、命令或子代理消息。
- 当自然 `end_turn` 的唯一阻塞是子代理状态时，在同一 ACP 会话内最多进行一次只读 `list_agents`/有界 `wait_agent` 对账；它与既有 pending-plan 续做分别计数，且不会触发 finalization 或会话替换。
- 对账超时会毒化并退休精确会话；流式和非流式处理器均补上退休重试与 snapshot fence，防止已退休/force-dead 会话被旧快照重新持久化。

### 验证

- 原始日志/rollout 已逐项对时，确认子代理实际完成、父代理持有旧快照的失败链路。
- `tests/test_acp_prompt_continuation.py`：71 passed；`tests/test_acp_client.py` 与 continuation 联合：186 passed。
- ACP client、continuation、session fence、completion guard、programming response/card session、prompt finalization 组合回归：442 passed。
- 涉及文件 Ruff 全通过；`git diff --check` 通过；`uv run python -m src.main --validate` 通过。
- 更早的同工作树非慢速全套基线为 `12397 passed, 1 skipped, 114 deselected, 57 subtests passed`；最终生命周期调整后以本节的直接相关组合回归作为收尾门禁。
- 提交前冻结工作树重新执行完整 non-slow suite：`12457 passed, 1 skipped, 114 deselected, 2 warnings, 57 subtests passed`，耗时 `477.48s`；两条 warning 仍为既有 `lark_channel` Python 3.13 deprecation warning。

### 风险

- 未知或结构损坏的 provider 子代理元数据会有意保持 incomplete，而不会猜测为成功；用户侧只看到安全诊断，需要 provider 修复或下一轮取得可验证终态。
