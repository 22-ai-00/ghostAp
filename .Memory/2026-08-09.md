## Slock 能力整体退役

### 决策与边界

- 按用户要求删除旧群、模式、任务看板、讨论、角色、卡片、恢复与兼容迁移能力，不保留产品入口。
- 保留 Autonomous Team、员工身份、Journal 数据、记忆、会话、知识、凭据和独立 workspace。
- 员工执行改由 TeamRuntime、EmployeeTeamGateway 与 EmployeeSessionHost 直接承载，不再要求激活群引擎。
- 默认员工存储继续指向既有数据目录，避免已有 MEMORY、NOTES、AGENTS、历史和 workspace 失联。

### 修改

- 删除旧引擎目录、飞书 Handler/dispatch、旧兼容层、专项文档、UX 和测试。
- 新增员工执行身份、独立 Session Host、Team Runtime 和只读 Team Memory adapter。
- 清理飞书路由、卡片动作、Slash 目录、配置样例及当前产品文档中的旧入口。
- Team Gateway 直接解析项目根、员工身份和独立会话；同时兼容 Team Journal 的 v2 与既有 `team.effect.*` 事件，超时取消先锚定再中断会话。

- 普通 ACP 任务在 pending 计划或安全选择时最多自动续做三轮，采用文档推荐或最小可逆本地默认，不再因普通实现选择打断用户。

- Workflow 新增统一 `WORKFLOW_AUTO_EXECUTE=true` 设置，生成并验证后默认直接执行；移除模块导入时读取环境变量造成的类似缓存行为。自动启动失败时保留可恢复确认卡及开始按钮。

### 数据连续性与设备迁移说明

- 同机升级会继续发现旧员工目录；不能只靠 `git pull` 在新设备恢复员工，因为身份事实、Journal、加密材料和 workspace 均是本地状态，不属于代码缓存。
- 跨设备必须成套迁移 `~/.ghostap/autonomy`、员工存储根、凭据目录及匹配的显式密钥配置；只复制员工目录会缺少 Journal 身份，缺少 runtime secrets 会导致旧加密数据无法解密。
- 精确 ACP 后端 session ID 目前不跨进程恢复，但员工稳定身份、逻辑会话键和重新建立会话的能力保留；后续若要求无缝恢复模型后端上下文，需要单独持久化并校验 backend session ID。
