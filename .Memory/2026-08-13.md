- 修复关闭边界：Runtime 已进入 closing 时，在启动凭据解析前将已锚定的 Slash effect 收口为 `recovery_exhausted` 并取消活动；凭据解析自身失败或取消也使用这一可重放终态。只有真正开始 `reconciler.reconcile()` 后，才把外部 mutation 标记为已开始。
- 修复历史自愈：Slash reconciliation 本身先 GET、按差异收敛、再 GET 精确验真，因此完整 prior activation 和精确六帧尾证据下的 `terminal_anchor_failed` 也允许跨 writer epoch 原子重开；兼容旧恢复器在下一 epoch 追加同 generation crash、再进入 ACTION_REQUIRED 的精确七帧形态。其他 effect 类型、额外元数据、同 epoch 与不完整证据仍拒绝。

## `/btw` 运行中只读旁路

- 根因：`/btw` 虽由 system fast lane 并发接收，却被连同命令前缀再次送入普通编程入口；新的 scheduler run 会重新申请主任务已持有的 repo lock，因而直接返回“仓库当前被其他任务占用”。即使跳过 repo lock，同一个 ACP session 也不允许并发 prompt。
- 修复：普通编程 handler 按 chat/project/thread 登记活跃任务及有界 ACP 事件快照；运行中的 `/btw` 改用相同工具、模型和 cwd 的全新辅助 session，只读回答当前任务、最近分析和工具状态。辅助 session 沿用 `create_auxiliary_session` 的强制 deny-all 工具策略，不会写仓库或干预主任务；同一主任务最多同时处理一个旁路问题，启动、回答和清理均有界，失败时返回可见进展且主任务继续。
- 空闲语义：当前编程模式没有正在执行的任务时，仅把 `/btw` 后的问题正文送入普通会话，不再把 GhostAP 控制命令泄漏给 provider。
- 验证：普通编程 adapter、完成判定、响应、direct lane 与 system 路由共 `186 passed`；WebSocket 路由全量 `157 passed`；相关 Ruff、`git diff --check` 和 `uv run python -m src.main --validate` 通过。第三方 protobuf 仍有既有弃用 warning，配置仍提示既有 `legacy_allow_all` break-glass warning。
