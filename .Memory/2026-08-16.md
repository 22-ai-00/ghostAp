## 修复 macOS restart readiness 误超时

### 任务与现象

- 用户执行 `./restart.sh` 后，Python 服务日志已出现
  `GhostAP restart readiness published generation=...`，脚本仍在 60 秒后返回
  `启动失败：服务未在 60s 内通过 readiness 检查`。
- 故障期间 Codex ACP fallback 安装成功，真实模型预热得到 7 个模型；依赖同步不是阻塞点。

### 根因

- `get_running_pids()` 遍历系统全部进程时，先对每个 PID 调用 macOS `lsof`
  检查 cwd，最后才过滤命令。进程较多时，一次发现扫描即可耗尽 readiness 预算。
- macOS `launchctl remove` 是异步停止：旧 GhostAP 仍会继续优雅退出约 5 秒。
  脚本若立即复用相同 label，`launchctl submit` 可能没有产生新的可运行进程。
- `launchctl submit` 后原实现把 `STARTED_PID` 留空，readiness 只能再次依赖全系统
  进程扫描，无法使用 launchd 已知的权威 PID。

### 修改

- `pid_is_ghostap_service()` 先按精确启动命令过滤，再对候选 PID 检查项目 cwd，
  避免对无关系统进程执行 `lsof`。
- 新增 launchd PID 查询、旧 job PID 退出等待和新 job PID 有界获取；启动后将
  launchd 返回的 PID 直接传给 readiness gate。
- `stop_service()` 在移除 launchd job 前固定已发现的服务 PID，并等待这些 PID
  退出；`launchctl submit` 或 PID 获取失败现在立即返回明确启动失败，不再空等 60 秒。
- 为命令预过滤、旧 launchd PID 等待、新 PID 获取和启动失败传播补充回归测试。

### 验证

- `uv run python -m pytest tests/test_restart_script.py -q`：`24 passed`。
- `uv run python -m src.main --validate`：配置校验通过，无安全发现。
- `bash -n restart.sh` 与 `git diff --check`：通过。
- 真实 `./restart.sh restart`：11.52 秒返回成功；PID `59530`，日志记录
  `[RESTART] start ready ... generation=ghxIK5YuyiQdkZ5Acwb9I_JfWUPpIqVg`。
- `./restart.sh status`、PID/命令检查及 `restart_gate ready` 均确认同一运行实例；
  Codex 模型预热 `count=7`，主 Agent 58 条 Slash Commands 同步完成。

### 后续风险

- 本机 Aiden/Gemini/Traex 命令缺失、Grok 未认证仍会产生非阻塞预热警告；它们不影响
  GhostAP 主服务、飞书长连接或 Codex ACP readiness。

## ACP 懒启动与 Bot readiness 解耦

### 现象与根因

- `restart.sh` 在每次启动前默认执行
  `npx --yes @agentclientprotocol/codex-acp@1.2.0 --version`；npm 网络慢或不可用时，
  Bot 进程尚未启动就会被 Codex adapter 预热拖住。
- `Application.run()` 又默认并发探测 Coco 以及六个 ACP 工具的模型目录；虽然为
  daemon thread 且不 `join`，仍会在飞书长连接 readiness 前创建 Codex/TraeX 等
  ACP 进程、发起网络请求并与主启动争用资源。

### 修改

- `GHOSTAP_PREPARE_CODEX_ACP` 的 restart 默认值从 `1` 改为 `0`；默认路径仅记录
  `preheat skipped`，不调用 native Codex 探测或 `npx`。仍保留显式设为 `1` 的运维
  opt-in，不删除固定 adapter 版本和预装能力。
- `acp_model_preheat_on_startup` 默认值改为 `False`，`Application.run()` 的缺省回退也
  改为 `False`。Bot 启动/readiness 不再主动建立任何 ACP 连接；真实 `/codex`、
  模型选择或编程任务仍通过原有 session factory 按需建连。
- ACP 交互期启动仍使用有界重试；首次网络失败不写入半成品 session，用户下一次
  飞书激活可重新创建。新增回归冻结“首次失败、第二次成功”契约。

### 验证与后续风险

- `tests/test_restart_script.py`：`26 passed`，包含默认路径不调用 Codex/native/npx 外部
  探测、主进程不预热以及显式 opt-in 仍可用。
- ACP 启动/模型缓存/直接编程/restart 相关套件：`186 passed`；非 slow 全量：
  `4326 passed, 26 deselected, 43 subtests passed`。
- `bash -n restart.sh`、受影响文件 Ruff、`git diff --check`、配置校验与测试资产
  清单均通过；当前实读 `acp_model_preheat_on_startup=False`，且无环境变量反向覆盖。
- 取舍是首次打开模型选择或 Codex 会话需承担冷启动；这个延迟现在只影响该次
  编程交互，不再影响飞书 Bot 上线。若网络仍不可用，交互返回明确失败后可再试。
