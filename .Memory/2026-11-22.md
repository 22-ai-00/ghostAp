# 2026-11-22

## AGY Effort 与 Orchestrator Planner/Executor Effort 完整支持

### 问题与实测发现

- 在本机升级 `agy` 至 `1.5.14` 后实测协议行为：
  - 常规模型（`gemini-4-neon`、`gemini-4-hydrogen`、`gemini-4-carbon`、`gemini-4-argon`、`gemini-3.8-flash`、`claude-opus-5-5`、`claude-sonnet-5-5`）在 `agy acp` 的 `configOptions` 中暴露 `thought_level`（`low`/`medium`/`high`，Neon/Hydrogen 另含 `xhigh`）。
  - 消费级账号上的三种 Orchestrator 模型（`gemini-pro-orchestrator-neon`、`gemini-pro-orchestrator`、`gemini-pro-orchestrator-argon`）在 `agy acp` 1.5.14 中不暴露 `thought_level`，调用 `session/set_config_option("thought_level", ...)` 返回 `-32602`，且 `agy acp` 会忽略 `settings.json["orchestrator"]`。
  - 实测验证 `agy 1.5.14` CLI 无头模式 `agy --prompt=... --output-format stream-json --dangerously-skip-permissions --model <orch_id> --settings '{"showThinking": true, "orchestrator": {"planner": "<Display Label>", "executor": "<Display Label>"}}'` 在消费级计划上严格生效，`--conversation <conversation_id>` 可跨轮无缝续接且支持中途切换 Planner/Executor。
  - `--settings.orchestrator` 要求传 `agy models` / `availableModels` 中的完整展示标签（如 `"Gemini 4 Neon (XHigh)"`、`"Gemini 4 Hydrogen (Low)"`，注意 `xhigh` 必须为 `"XHigh"`），传 slug 会静默回落默认配置。

1. **选择编码、标签解析与归一化（`src/acp/agy_selection.py`）**

### 后续风险

- `SyncAGYCLISession` 通过 CLI `stream-json` 执行消费级 Orchestrator 自定义 Effort，不支持原生 ACP `/swarm` 后台协作等待周期（如需 `/swarm`，选择常规 AGY 模型或默认 Orchestrator `Planner Effort = default` 即可走原生 ACP）；若后续新版本 `agy acp` 原生在 `configOptions` 中为 Orchestrator 暴露 `thought_level` 或 planner/executor 选项，GhostAP 会自动优先原生 ACP，届时可进一步精简 CLI 分支。
