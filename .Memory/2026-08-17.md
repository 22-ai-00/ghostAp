## 主 Bot 审计 Journal 快速恢复

- 根因是 `MainBotSendAuditLog.open()` 使用通用 `JournalWriter.open()`，
  启动时把 382 MiB、382771 帧逐帧 JSON 解码、重建 canonical payload、
  校验 HMAC 并全部常驻 `_frames`；其中 379788 帧是高频卡片 patch。
- 为严格的单 aggregate 追加账本新增 `open_at_verified_tail()`：流式扫描
  原始物理帧并核对每一帧的 SHA-256 `previous_hash` 链、帧数、外部 anchor
  和尾帧 HMAC，但只物化已锚定尾帧及其 aggregate version。每次新提交后
  也只保留最新帧，因此没有删除、迁移或压缩任何历史审计证据。
- `replay()` 保持原有完整 JSON/HMAC 验证，用于真正的历史计数查询；查询
  期间发现任何损坏会将审计标为 incomplete，后续 activation fence
  fail-closed。专用 writer 同时拒绝其他 aggregate，并拒绝从内存 tail
  冒充完整 `committed_tail`。

## Employee Channel 退出竞态修复

- 事件管道 EOF 与子进程退出状态存在短暂竞态：reader 线程首次 `poll()`
  可能仍得到 `None`，随后虽然回收到了退出码，状态却已固化为
  `FAILED/event-pipe-closed`，掩盖真实的 worker 非预期退出。
- EOF 后增加 100ms 有界退出宽限；宽限内自然退出（包括退出码 0 但未走
  STOP 协议的退出）统一记录为 `CRASHED`，仍存活的断管 worker 保持原有
  `FAILED/event-pipe-closed` 并被终止，未放宽失败关闭语义。

## 本地密钥并发引导修复

- Darwin 上多个线程同时通过同一目录 fd 执行 `openat(O_CREAT)` 创建本地
  runtime lock 时，会稳定出现瞬时 `ENOENT`；原实现将其直接包装为引导失败，
  导致同进程并发启动不能收敛。
- 新增仅针对 lock open 的 8 次有界重试，只重试 `ENOENT`；其他错误立即失败，
  持久目录消失或替换仍会在预算耗尽后 fail-closed。`O_NOFOLLOW`、所有者与权限
  校验以及后续 `flock` 均保持不变。
