## 飞书聊天图片统一迁入用户缓存

- 根因：`FeishuImageHandler.get_image_save_dir()` 优先返回
  `<project_root>/picturechat`，无项目时才回退到聊天工作目录；因此飞书入站图片
  会污染每个项目的源码目录，而 Deep、Spec、Workflow 和普通编程实际都在同一
  WebSocket 路由点下载并消费这些图片。
- 图片保存根目录统一改为 `~/.cache/ghostAp/picturechat`。项目根目录和聊天工作
  目录不再参与路径计算；图片绝对路径仍在具体编程模式分流前追加到原始 prompt，
  所有模式继续共享同一份入站图片。
- 集中缓存后不能再依赖消息 ID 末 8 位隔离目录。消息子目录改为完整消息 ID 的
  SHA-256：`msg_<64 hex>`，既避免跨项目/聊天的尾部碰撞，也不在缓存目录名中
  暴露飞书消息 ID。
- `picturechat` 和消息目录使用 `0700`，图片使用 `0600`；打开图片文件时在
  Linux/macOS 可用时增加 `O_NOFOLLOW`，避免跟随同名符号链接。删除仓库对
  `picturechat/` 的忽略规则，让未来误写回项目目录能直接出现在 Git 状态中。
- 盘点 `~/.ghostap/projects.json` 中 11 个注册项目，发现
  `/home/jiataorui/work/github/dsh-enhanced/picturechat` 尚有 1 张旧缓存图；已将其
  原样移动到 `~/.cache/ghostAp/picturechat/msg_8d60aa1c/1.png`，收紧权限并删除
  项目内空目录。该迁移可通过把消息目录移回旧路径恢复。

## macOS 飞书 SDK 单文件导入缓存

- 根因不是 `uv` 重复安装。`restart.sh` 的 `uv sync --check` 只耗时 0–1 秒，
  真正的冷启动瓶颈是 `lark-oapi==1.7.2` 顶层急切导入约 1 万个生成模块；本机
  `src.feishu.ws_client` 普通目录导入对照为 17.10 秒，历史真实启动中飞书运行时
  导入与组装合计达到 51.7 秒。
- 新增 `src/utils/lark_import_cache.py`：将当前 `uv` 虚拟环境已经生成且通过
  pyc header 校验的 `lark_oapi` 字节码打包为一个无源码、无压缩的 zipimport
  归档，放在 `.venv/.ghostap-import-cache/`。缓存键同时绑定 wheel `RECORD`、
  Python `cache_tag` 和 bytecode magic；SDK 或 Python 变化时原子重建，成功后只
  清理同包旧缓存。
- `src.main` 在任何飞书模块导入前激活该缓存，并分别记录缓存构建/复用及飞书
  运行时导入耗时。缓存构建或环境只读等异常只记录类型并回退到 `uv` 管理的原始
  site-packages，不改变 WebSocket、reply-chain 和审计 readiness 条件。
- 实现仅使用 Python 标准库的 `pathlib`、`py_compile`、`zipfile` 和原子
  `os.replace`，不依赖 macOS `zip` 命令或 Linux 专有系统调用；Linux 与 macOS
  共享同一代码路径。缓存目录/归档权限分别为 `0700`/`0600`。

### 验证

  缓存名、旧分发缓存未清理时各有 1 个精确失败。实现后专项 `4 passed`。
- 真实基准：缓存复用 0.03 秒；`lark_oapi` 单独导入约 1.3 秒；完整飞书运行时
  导入 2.72 秒。`ws_client` 同轮普通目录/缓存对照为 17.10/4.08 秒。
- 消息、卡片、Employee、restart 专项 `140 passed, 1 skipped`；WS 路由与配置
  扩展回归 `305 passed`；非慢速全量 `4509 passed, 4 skipped, 26 deselected,
  43 subtests passed`。
- 真实 macOS `./restart.sh`：上一轮 readiness 55 秒；优化后 PID `45553` 在

  异步完成。

### 后续风险

- 首次创建或 SDK/Python 升级后会一次性构建约 31 MiB 缓存，本机耗时约 20 秒；
  后续启动只读 wheel RECORD 和 zip 中央目录。缓存属于 `.venv` 派生产物，可随
  虚拟环境安全删除并自动重建。
