## 修复跨工具切换残留 `acp_model_name` 导致 Traex 续窗报错与异常后处理 `UnboundLocalError`

### 问题与根因

- 巡检 [logs.log](file:///data00/home/jiataorui/work/github/ghostAp/logs.log) 发现 `dsh_enhanced` 项目在 00:39 从 `agy`（保存了 `gemini-pro-orchestrator`）通过 `/traex`（`enter_traex`）切换至 `traex` 时，窗口 1 以 `model_name=None` 正常启动，但在窗口 2 续开时报错 `RuntimeError: Traex ACP rejected selected model: gemini-pro-orchestrator`，同时伴随 `UnboundLocalError: cannot access local variable 'result'`。
- 根因定位：
  1. `ProgrammingModeHandler._set_mode_on_project()`（`src/feishu/handlers/programming.py`）在写入 `project.acp_tool_name = self.mode_key` 时，未在跨工具切换（`previous_tool != self.mode_key`）且未显式传 `model_override` 时清理旧工具遗留的 `project.acp_model_name`，导致项目持久化状态被污染为 `acp_tool_name="traex"` + `acp_model_name="gemini-pro-orchestrator"`（线上 `~/.ghostap/projects.json` 中 `dsh_enhanced` 与 `aifriendly` 均受此影响）。
  2. `_resume_window()`（`src/feishu/handlers/programming_execution.py`）与 `_replace_timed_out_session()`（`src/feishu/handlers/programming.py`）续开/重建会话时读取了可变的 `project.acp_model_name`，而非优先继承当前运行会话实际绑定的 `_model_name`。
  3. `_execute_programming_response()`（`src/feishu/handlers/programming_execution.py`）进入 `try:` 前未预先初始化 `result = None`，任意窗口/启动异常都会导致 line 1156 读取 `result.modified_files` 时抛出 `UnboundLocalError` 并跳过上下文持久化。
  4. `DiagnosticsHandler._collect_programming_summary()` 与 `SystemHandler.handle_clear_command()`（以及 `ProgrammingModeHandler._register_thread_context()`）在读取 `project.acp_model_name` 前未校验 `project.acp_tool_name == active_tool`。

## 实现 AGY 与多群/多项目/多话题完整 Context 隔离

### 排查结论（已隔离项 vs 真实泄漏点）

- **已隔离部分**：`ACPSessionManager` 按 `SessionKeyCodec.encode(chat_id, project_id, thread_id)` 为每个 `(chat_id, project_id, thread_id)` 独立拉起 `agy acp` 子进程与唯一 `session_id`（Orchestrator 自定义 effort 走 `SyncAGYCLISession` 独立 `--conversation` UUID）。实测本机 `agy 1.5.14` 同一目录并发双会话无 prompt 对话记忆混用。
- **真实串联缺口**：
  1. `ProgrammingModeHandler._current_model` 为进程级单例字段，Group A 设置模型/effort 后通过 `_get_model_name_override()` 泄漏给未绑定或切工具中的 Group B/其他项目，且并发激活回滚会互相踩踏。
  2. 多群共享同一 `ProjectContext`（如 `/new-chat` 项目群与私聊共用、或多群切入同一项目）时，顶层 `acp_tool_name`、`acp_model_name`、`_active_modes`、`session_snapshots` 跨群共享，群 B 的 `/model`、`/effort`、`/acp`、`/exit`、`/clear` 会直接覆盖群 A。
  3. `ProjectContextManager`（`UnifiedContext`）未实现 `.clear()`，`/clear` 无法清空内存对话与桥接摘要；且未将 `thread_id` 纳入存储键，导致同一 `(chat_id, project_id)` 下话题与主聊天争抢/消耗 `bridge_summary`。
