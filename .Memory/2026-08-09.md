- 正确性：child rollout 已存在但最新 turn 仍 running、归属不匹配或结构含糊时 fail closed，并禁止回退到父 rollout 中可能陈旧的 `agentsStates` / `list_agents` 快照；完全没有 child rollout 能力时才保留旧 fallback。

## 四模式与 Dynamic Workflow 静态契约收口

### 自动推进审计

- 普通编程：会话缺失只自动重建一次；统一 deadline、plan continuation、子 Agent 对账、自动决策和 Goal 恢复均有次数上限；安全推荐自动采用，高风险自动拒绝。
- Deep：有效任务直接启动，固定最多 2 次 continuation，终态只能 complete/cancel/fail；`/deep_update` 仅消费用户主动追加队列，不是等待确认。
- Spec：有限 cycle；自动恢复次数新增到现有 checkpoint，默认跨重启最多一次，次数耗尽或 claim 持久化失败即写明确失败终态。
- Workflow：推荐工具、默认模型、Auto reviewer，最多 3 次脚本生成，随后直接执行冻结 RunSpec；删除 Engine 旧 legacy run-spec 伪造入口，唯一执行 API 强制传入 `run_spec`。

### Workflow 算法与卡片新增收口

- `verify()` issue 现在必须包含 `severity/description/evidence`，Runtime 执行 closed-object、枚举及非空校验；拒绝但无 issue 的 Review 无效；结果新增完整 `reviews` 和扁平 `evidence` ledger。
- `race()` 的声明式 contestant 继承原语 timeout，deadline 到期取消仍挂起请求并返回明确 `race_timeout`。
- Bridge stderr 设置单行 4 KiB、总诊断 64 KiB 上限；实时日志、tail 和退出 drain 采用同一限制并保留截断标志。
- Workflow 卡片失败 Agent 的 token 与 duration 不再丢失，会进入阶段与总计指标；权威 direct-agent、单条当前操作、attempt、阶段、完整结果分页和 HTML 兜底链路静态成立。

### 最新体量

- 生产 Python 136,558 行、JS 1,840 行，生产合计 138,398 行；测试 68,156 行；总计 206,554 行。
- 相对 413,233 行基线删除 206,679 行，整体减幅约 50.015%，增强算法后仍严格低于基线一半。

### 尚未闭合的证据与边界
