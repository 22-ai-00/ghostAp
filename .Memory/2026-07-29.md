## 编程长任务终态、卡片错误与安全重启加固

### 生产现象与证据

- 用户截图中的 Codex 主卡创建于北京时间 12:47:05（日志 UTC
  04:47:05），并在 UTC 06:47:07 精确触发 `ACP prompt 执行超时
  (7200s)`；期间累计 18,601 个 ACP 事件。
- 同一 CardKit 卡片的创建、流式 PUT 和终态 PATCH 均返回 HTTP 200，
  因此红色错误卡不是飞书卡片 API 失败，而是 GhostAP 按 ACP 硬截止
  正常写入的失败终态。
- 子任务摘要中出现裸 `"formatted_output": "FFFFFF`。完整 JSON 清洗虽
  已存在，但被截断后以引号键开头、没有外层 `{` 的成员片段绕过结构化
  内容识别，被误当成了子任务显示标签。
- 首轮非慢速全量还暴露 5 个可靠性改动的兼容回归：retry 锁 owner 调用
  契约、Claude Popen 进程组测试替身、TTADK 早期异常初始化、leaf lock
  注解、manager closing registry 测试夹具。第二轮全量又捕获一次性计划
  文档违反仓库瘦身门禁，以及旧 action-retry 测试未跟进显式 owner 契约。

### 根因

- 普通编程调用把完整 7200 秒预算全部交给首轮 prompt。达到硬截止后只能
  直接失败，没有独立预算要求 Agent 停止扩展、收拢子代理、保存已有成果、
  执行最必要验证并给出最终答复。
- 超时、取消、关闭与 session 重建之间缺少完整的同一性和事件代际围栏；
  关闭失败或迟到事件可能污染后续 turn，CLI 子进程的后代还可能继续持有
  stdout/stderr 导致父进程无法可靠收尾。
- 仓库锁按固定 3600 秒硬时长回收，而 ACP 任务允许 7200 秒；仅按 chat
  标识可重入也允许同群旧请求触碰或释放新请求的锁。
- 卡片子代理摘要同时承载 provider 原始 tool payload 和用户显示标签，
  对失败终态、重复终态、未知状态及截断结构化片段缺少足够严格的类型边界。
- 远程重启脚本只延迟后停止进程，没有跨 checkout 稳定门禁、任务排空、
  generation/readiness 身份确认和全预算进程组清理。

### 修改

- ACP 与普通编程终态：
  - 新增 `src/acp/finalization.py`，在配置的总预算内拆分首轮执行与有界
    finalization turn；默认从 7200 秒中预留 600 秒，收尾提示禁止扩大范围
    或新增子代理，只允许完成原任务授权的必要收尾。
  - 超时 session 在复用前必须标记 `_force_dead` 并退休；必要时在剩余预算
    内重建 finalization session。manager 使用 per-key closing tombstone、
    有界 close 和同一 session 比对，sync adapter 增加 prompt generation
    事件栅栏，迟到事件不能进入新 turn。
  - Claude/TTADK CLI 使用独立进程组、watchdog 和统一 terminate/reap
    路径；即使环境构造、wait、BaseException 或 leader 先退出，也会清理
    后代并把不可确认终止的 session 标成不可复用。
- 卡片与子代理摘要：
  - 新增统一的 tool display 清洗，首个可信的人类任务标签和首个终态获胜；
    失败只提取显式 error/message/reason/detail/stderr 字段，限制长度并移除
    call ID、命令、ANSI/OSC、控制字符、Markdown 元字符、图片引用和机密。
  - 识别完整 JSON、未闭合对象/数组，以及以 `"key":` 开头的截断成员；
    截图中的 `"formatted_output": "FFFFFF` 现在稳定回退为“子任务”。
  - parent 超时只把仍在运行的子任务标为取消，不伪造失败或成功；未知状态
    以橙色“未知”展示，渲染边界再次净化 label/tool/model/sequence/error。
  - CardKit 页面变更和终态投递增加单调栅栏，旧 patch/迟到事件不能覆盖
    更新版本或终态。
- 锁、调度与重启：
  - repo lock owner 提升为 `(chat_id, scheduler_run_id)`，心跳持续续租，
    旧请求不能触碰或释放同群新请求；调度器和 bounded executor 补齐
    BaseException 下的终态/slot 释放。
  - 新增 checkout 外的私有 restart gate、稳定 locator、generation 快照、
    任务排空、单次重启和总预算；停止/启动使用进程组清理，只有 WebSocket
    已连接且 PID/启动指纹匹配后才发布 ready generation。
  - WebSocket 资源管理、重连、健康状态和主进程关闭顺序同步加固，确保
    restart worker 能区分 Python 冷启动、连接未就绪与真实启动成功。
- 配置、README、`.env.example` 和针对性测试同步更新；修复全量门禁发现的
  兼容夹具与显式 owner 断言，不削弱进程组、closing registry 或锁 owner
  新契约。

### 风险与后续

- 默认 7200 秒总预算不变，但首轮 prompt 的可用预算变为 6600 秒，剩余
  600 秒专用于安全收尾；配置可调整 reserve，仍受比例和最小首轮预算限制。
- 历史已发送错误卡不会自动重写；修复只作用于新事件和后续任务。
- 本轮未直接重启线上服务；安全重启、WebSocket readiness 和新配置在下次
  受控启动后生效。
