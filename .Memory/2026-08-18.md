## 飞书聊天图片统一迁入用户缓存

- 根因：`FeishuImageHandler.get_image_save_dir()` 优先返回
  `<project_root>/picturechat`，无项目时才回退到聊天工作目录；因此飞书入站图片
  会污染每个项目的源码目录，而 Deep、Spec、Workflow 和普通编程实际都在同一
  WebSocket 路由点下载并消费这些图片。
- 图片保存根目录统一改为 `~/.cache/ghostAp/picturechat`。项目根目录和聊天工作
  目录不再参与路径计算；图片绝对路径仍在具体编程模式分流前追加到原始 prompt，
  所有模式继续共享同一份入站图片。
- 集中缓存后不能再依赖消息 ID 末 8 位隔离目录。消息子目录改为完整消息 ID 的
  SHA-256：`msg_<64 hex>`，既避免跨项目/聊天的尾部碰撞，也不在缓存目录名中
  暴露飞书消息 ID。
- `picturechat` 和消息目录使用 `0700`，图片使用 `0600`；打开图片文件时在
  Linux/macOS 可用时增加 `O_NOFOLLOW`，避免跟随同名符号链接。删除仓库对
  `picturechat/` 的忽略规则，让未来误写回项目目录能直接出现在 Git 状态中。
- 盘点 `~/.ghostap/projects.json` 中 11 个注册项目，发现
  `/home/jiataorui/work/github/dsh-enhanced/picturechat` 尚有 1 张旧缓存图；已将其
  原样移动到 `~/.cache/ghostAp/picturechat/msg_8d60aa1c/1.png`，收紧权限并删除
  项目内空目录。该迁移可通过把消息目录移回旧路径恢复。
