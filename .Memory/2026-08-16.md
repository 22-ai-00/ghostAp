# 2026-08-16

## 修复 macOS restart readiness 误超时

### 任务与现象

- 用户执行 `./restart.sh` 后，Python 服务日志已出现
  `GhostAP restart readiness published generation=...`，脚本仍在 60 秒后返回
  `启动失败：服务未在 60s 内通过 readiness 检查`。
- 故障期间 Codex ACP fallback 安装成功，真实模型预热得到 7 个模型；依赖同步不是阻塞点。

### 根因

- `get_running_pids()` 遍历系统全部进程时，先对每个 PID 调用 macOS `lsof`
  检查 cwd，最后才过滤命令。进程较多时，一次发现扫描即可耗尽 readiness 预算。
- macOS `launchctl remove` 是异步停止：旧 GhostAP 仍会继续优雅退出约 5 秒。
  脚本若立即复用相同 label，`launchctl submit` 可能没有产生新的可运行进程。
- `launchctl submit` 后原实现把 `STARTED_PID` 留空，readiness 只能再次依赖全系统
  进程扫描，无法使用 launchd 已知的权威 PID。

### 修改

- `pid_is_ghostap_service()` 先按精确启动命令过滤，再对候选 PID 检查项目 cwd，
  避免对无关系统进程执行 `lsof`。
- 新增 launchd PID 查询、旧 job PID 退出等待和新 job PID 有界获取；启动后将
  launchd 返回的 PID 直接传给 readiness gate。
- `stop_service()` 在移除 launchd job 前固定已发现的服务 PID，并等待这些 PID
  退出；`launchctl submit` 或 PID 获取失败现在立即返回明确启动失败，不再空等 60 秒。
- 为命令预过滤、旧 launchd PID 等待、新 PID 获取和启动失败传播补充回归测试。

### 验证

- `uv run python -m pytest tests/test_restart_script.py -q`：`24 passed`。
- `uv run python -m src.main --validate`：配置校验通过，无安全发现。
- `bash -n restart.sh` 与 `git diff --check`：通过。
- 真实 `./restart.sh restart`：11.52 秒返回成功；PID `59530`，日志记录
  `[RESTART] start ready ... generation=ghxIK5YuyiQdkZ5Acwb9I_JfWUPpIqVg`。
- `./restart.sh status`、PID/命令检查及 `restart_gate ready` 均确认同一运行实例；
  Codex 模型预热 `count=7`，主 Agent 58 条 Slash Commands 同步完成。
