## Codex 子任务终态采集与启动合同根治

### 生产证据与根因

- 最新三次所谓子任务失败均为外层协作工具 `completed`、内部 child 快照仍是 `running`，分别留下 4、3、3 个 `unresolved_child_tool_calls`；没有对应的 child `failed/cancelled`。Codex rollout 已显示最终 `list_agents` 全部 completed，GhostAP 却仍判 `outcome=incomplete`。
- 兼容形态的 `list_agents` 带 `rawInput.agentsStates` 但没有 `_meta.codex.collaboration`，旧解析器直接丢弃终态；完成输出中的更新也未参与优先级合并。
- `ACPSession` 在 PromptResponse 后仅做 50ms 静默 drain，collector 解绑期间到达的 child 终态没有耐久承接；自动再发 wait/list 提示只能降低概率，不能根治。
- 显式 `agent_type` 与默认全历史 fork 组合会在子代理启动前被 Codex 拒绝。另有 worker 指令强制 diff/验证，与上层“未经要求不验证”规则冲突。

### 更改

- 协作解析增加严格 allowlist 兼容入口：仅可信的 collaboration 工具标题可从 `raw_input`/`raw_output` 读取 receiver 与 `agentsStates`，完成输出覆盖同调用的陈旧输入；未知工具不能伪造协作状态。
- `ACPSession` 增加有界的跨 prompt child 事件账本；collector 空窗收到的终态在下一 turn 原子回放。专用 reconciliation 入口仅等待真实 pending/running child，terminal 或 malformed 不会无界等待，仍由外层硬 deadline 兜底。
- 自动续跑修复缺失 `and` 的语法损坏；明确“请确认/请选择/请回复”等阻塞输入请求优先于 child reconciliation，避免越过用户确认；对账 turn 使用专用 child-quiescence 入口。
- 收尾通过实例能力调用 single-turn finalization，并禁止在最后预算内启动新验证。
- 项目规则明确 `agent_type` 与 `fork_turns` 合法组合；worker 候选配置同步收紧启动说明并移除强制验证/过早拒绝冲突。
- 补回归合同覆盖无 namespaced metadata 的终态、raw_output 权威覆盖、未知工具拒绝、300ms 迟到终态、collector 空窗回放、用户确认优先级和专用 reconciliation/finalization 调用。

## Codex 子代理超时收尾与取消终态归一

### 日志证据

- 截图对应 `logs.log` 中 2026-08-07 07:17:55.243 至 09:17:32.700 的唯一普通 Codex 执行，墙钟耗时 1:59:37.457，与卡片显示完全一致。
- 主阶段在 6599.999998 秒超时，随后进入 600 秒预留收尾；收尾 prompt 又在 572.715916 秒超时，之后精确 ACP session 被同步退休并关闭，最终结果为 `outcome=incomplete, stop_reason=timeout`。
- 事件窗口内没有用户停止、服务重启或 WebSocket 断连；五个未完成子代理的取消来自父 session 超时回收，而不是外部中断。生产日志不记录子任务名称或消息正文，因此未把卡片文本写入诊断。

### 根因

- 既有运行时收尾提示允许“等待或中止”子代理，模型可以继续调用 `wait_agent`，把约 573 秒收尾预算全部耗尽。
- 普通 prompt 必须在 PromptResponse 后继续等待 provider Goal 与 thread 真正静止，以免漏收 Codex 在数毫秒后自动续起的 turn；但已经暂停 Goal、且返回后必定退休 session 的最终收尾不需要继续跟随新的 Goal turn。
- ACP 子代理权威状态允许 `cancelled`，普通编程主卡和多任务编排器的重复映射却只识别 `interrupted`。终态 snapshot 还可能沿用“已与主 Agent 交互”等瞬态 message，造成取消后仍显示为运行或交互中的矛盾状态。

### 更改

- 收尾提示改为一次 `list_agents`、逐个 `interrupt_agent` 处理中间态、再次 `list_agents` 后立即终答；明确禁止 `wait_agent`、`spawn_agent`、`followup_task` 和 `send_message`，不再允许等待式收尾。
- `SyncACPSession` 增加仅供运行时收尾使用的 single-turn 入口。普通 prompt 仍等待 Goal 静止；收尾 prompt 保留直接 PromptResponse 前的事件与短尾部 drain，但不继续跟随新的 Goal turn，返回后沿用既有 poison + retire 路径。
- 普通主卡与 `TaskOrchestrator` 同步识别 canonical `cancelled`，并在 completed/failed/cancelled 转换时把已启动、执行中、已交互等瞬态进展替换成对应终态文案；真实终态结果文本继续保留。

### 验证

- 已将截图墙钟、两段 timeout、session retirement 与相邻重启/断连逐项对时，确认外部事件不是触发源。
- 按当前交互约束未运行测试、静态检查、配置校验或二次代码回读；本条不把未执行的验证声明为通过。

### 后续风险

- GhostAP 当前没有 host-side 子代理 list/interrupt RPC，收尾阶段的逐个中止仍依赖 Codex Agent 遵守高优先级提示；single-turn 边界只保证收到直接 PromptResponse 后不再跟随 Goal，不能强制打断 turn 内主动发起的长等待。
- 7200 秒总预算与 600 秒 reserve 保持不变。本次不以单个事故样本调整全局超时，也不放宽普通执行的 Goal 完成门禁。

## Workflow Reviewer 权限取消与失败终态修复

### 生产证据与根因

- 截图对应 Workflow 在 04:17:49 UTC 启动、05:45:56 UTC 失败；错误中的三条 Traex 是三个不同显式 Reviewer，不是同一任务重试。另一个 Traex 与 Codex Reviewer 正常完成。
- 三个失败会话在 `stop_reason=cancelled` 前均记录 `Permission safety check failed closed: ValueError`。ACP execute 权限桥只接受字符串命令，Traex 常见的 canonical argv 数组会在安全策略前被误判为畸形并返回 `DeniedOutcome(cancelled)`；旧日志未记录 payload shape，因此数组是与代码路径和生产时序一致的高置信根因，而非旧证据可百分百还原的原始 payload。
- 顶层 `Independent review failed` 文本包含子 Reviewer 的 `cancelled`，通用关键词分类把整次执行误报成生命周期取消，再映射为“状态不匹配”。失败回调另发错误卡而不替换进度卡，旧主卡继续保留停止按钮；用户两小时后点击它才产生第二张“状态不匹配”。
- 截图中的状态命令输入为 `/ws_status`，权威命令是 `/wf_status`（另支持 `/workflow_status`）；未知命令响应属于拼写错误，不是 dispatcher 双响应。

### 更改

- ACP execute 权限桥显式接受非空 `list[str]`/`tuple[str, ...]`，用 `shlex.join()` 保留 argv 边界，再继续经过既有 tool filter、危险命令检查与 sandbox 检查；危险 argv、空数组、嵌套数组、混合类型和 NUL 仍默认拒绝。
- 权限异常日志与 history 增加不含命令内容的 `stage`、`kind`、`command_shape`，以后可直接区分 payload 形状、tool filter、危险命令检查与 sandbox 故障。
- Workflow 新增独立评审失败分类，优先于嵌套 `cancelled` 关键词；Reviewer 仍必须以非空 `end_turn` 完成，失败关闭合同没有放宽。
- 失败回调原位替换当前进度卡，终态卡不再残留停止按钮；停止按钮注入显式读取权威 `RUNNING` 状态。历史旧卡的停止回调改为幂等返回当前终态，不再误报状态冲突。

## Workflow 消息卡终态全显与容量续接重设计

### 原因与产品合同

- 旧终态简报为了守住飞书卡片预算，会将过长或超量结果整条省略并仅显示“另有 N 条”；完整 HTML/Markdown 报告虽然保存了原文，但不能满足用户“每次最终结果必须显示”的主卡可见性目标。
- 本轮将信息分为两类：思考过程中的单步事情只占一个固定位置并原位替换；每个 Agent/Reviewer 的最终结果进入只追加账本，成为不可被后续进度覆盖、不可因容量不足而省略的产品合同。

### 核心改动

- 安全结果投影在既有泄漏防护和 Markdown 清理之后生成用户可见终态条目；成功、失败、空输出和 Reviewer 结论均保留明确身份、状态与完整结果，不把内部原始对象直接透传到卡片。
- 运行卡新增唯一“当前单步”槽位，心跳和流式过程只更新该槽；已完成结果使用稳定序号写入追加账本，终态只读取账本，不再从可能被覆盖的当前进度反推结果。
- 结果账本按卡片安全预算分页：新页成功可见后才冻结前页，页码、结果范围和连续序号明确标识；终态刷新所有结果页，不裁半句、不用遗漏计数替代真实结果。
- `WorkflowHandler` 与 `WorkflowScriptMixin` 两个入口复用同一分页投递路径，统一 origin/message 绑定、当前页推进、前页冻结、终态防迟到覆盖和有界失败处理，避免两套 callback 再次分叉或 PATCH 失败演变为卡片洪泛。
- 新增 `ux/workflow-message-card.html` 独立响应式预览，同页覆盖运行态、容量续接态、成功终态和失败终态；终态展示每个 Agent/Reviewer 结果、验证、交付物与下一步，且不保留停止按钮。

### 文件范围

- 生产改动限定在 `src/workflow_engine/` 的安全结果投影、状态/渲染与结果页模型，以及 `src/feishu/handlers/` 的两个 Workflow callback 入口和共享分页投递；未改变 ACP、JS runtime 或其他执行模式合同。
- 回归覆盖 Workflow renderer、progress summary、confirm/callback、结果账本和多页交付边界；UX 仅新增 `ux/workflow-message-card.html`，本条同时更新当日 Memory 与索引。

## Codex 终态剩余边界与全量门禁闭环

### 新发现与根因

- collector 空窗账本原本会被下一次任意 prompt 无条件并入；旧任务迟到 child 既可能在 prompt 之间进入 deferred ledger，也可能在新 prompt 已安装 collector 后到达，造成新任务被误判 incomplete、触发无关对账甚至串入新卡。
- 仅按旧 tool call id 隔离不足：Codex 可在后续 turn 用新 `list_agents` call id 再列出旧 source；反过来 provider 也可能复用旧 call id 但返回全新 source，不能把 call id 当永久黑名单。
- official Codex rollout 的 function output 可能晚于 ACP PromptResponse 数十毫秒落盘，单次读取会偶发错过已经发生且时间戳仍在本轮窗口内的权威终态。
- B063 确认可达：Spec 仍使用 `TaskOrchestrator` 独立子卡；同一稳定 source 经成功 `followup_task` 开启新 generation 后，旧终态集合会让主卡和独立子卡永久短路。并发 followup 还可能创建重复卡，reset/close 与新卡创建竞态可复活已清空的编排器。

### 修复

- ACP session 将普通用户 prompt 与同逻辑任务的 continuation/reconciliation/finalization 分离：只有专用同任务入口回放 deferred child；普通新任务丢弃旧 deferred，并使用会话期持久、有界的 call/source identity ledger 过滤迟到被动快照。
- identity ledger 各最多 512 项；旧 source 无论隔多少普通 prompt 都不能污染，新 call id 不构成绕过。成功 `spawn_agent/followup_task` 可显式解除对应 source 栅栏；旧 call id 若携带全新 source 也可重新归属当前任务。畸形 receiver/state 中可识别的旧 source 同样被隔离，未知畸形证据仍 fail-close。
- rollout fallback 在严格 session/cwd/原时间窗不变的前提下增加最多 200ms、20ms 间隔的 settle 重读；不回退 earlier terminal，latest malformed/running/未知 path 仍立即保持 incomplete。
- 主卡仅允许成功 `spawn_agent/followup_task` 重开终态 child；迟到 `started` activity 和普通 list/wait 快照继续保持终态单调。
- `TaskOrchestrator` 为已终态 child 创建新的物理子卡，旧卡不可变；overflow 共享卡按物理 resolved id 换代。新卡创建、首帧投递失败均保留旧终态并 fail-close。
- generation claim 按物理卡串行化并发 followup；lifecycle epoch 将 reset/finish/close 与换代提交线性化，等待者在 epoch 变化后退出，迟到 owner 不能复活 sessions。首次投递前后双重校验，失效临时卡归档且 bridge 关闭，所有外部 I/O 均在 leaf lock 外。
- 全量门禁另暴露 12 条既有合同漂移：统一执行流下普通主卡故意隐藏重复 tool footer，Workflow 默认路径已改为 `GENERATING_SCRIPT + auto_reviewer`，错误枚举新增 `REVIEW_FAILED`，CardKit route lock 缺 leaf 注释。测试与生产类型守卫已同步，`_init_tool_selection_state` 不再接受 MagicMock/非 `PendingConfirmation` 假 pending。
