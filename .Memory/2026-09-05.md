# 2026-09-05

## 项目群 `/dsh` 默认开放与准入模式可见化

### 根因

- `/dsh` 已完整注册为一等普通编程入口，阻断不在 DSH provider 或模型配置。
- 新机器的代码默认和 `.env.example` 都使用 `INGRESS_ACCESS_MODE=enforced`；该模式要求
  sender 同时属于 `ADMIN_USER_IDS`/`ALLOWED_USER_IDS`，chat 同时属于
  `ALLOWED_CHAT_IDS`。任一维为空都会在 `/dsh` 解析前静默拒绝。
- WebSocket 还有独立 Registry trust gate。非现役 Managed Group 会解析为
  `EXTERNAL_OR_UNKNOWN_GROUP` 并在 access policy 之前拒绝，因此只把 policy 设成开放
  仍不足以让旧项目群或普通群直接使用。

### 修改

- `Settings`、`.env.example` 和 README 将新安装默认改为
  `INGRESS_ACCESS_MODE=legacy_allow_all`。当前飞书 App 实际收到的规范私聊/群聊消息可
  直接进入 `/dsh`、其他编程入口、Shell 和 Workflow。
- legacy-open 模式现在显式贯穿 intake trust decision、worker action gate、dispatch
  revision recheck 和 `MessageDispatcher`；unknown group 不再被第二层静默吞掉。
- 显式 `INGRESS_ACCESS_MODE=enforced` 行为不变：unknown group 仍拒绝，受管群继续要求
  Registry + ProjectGrant + revision 完整匹配，管理员与 Employee 专项授权没有放宽。
- `uv run python -m src.main --validate` 新增 `[飞书入口]` 区块并显示实际
  `INGRESS_ACCESS_MODE`，便于发现旧 `.env` 仍覆盖新默认。
- 已有机器不会被升级自动改写 `.env`。若旧文件含 `INGRESS_ACCESS_MODE=enforced`，需
  手动改成 `legacy_allow_all` 后重启；新安装无需配置 user/chat allowlist。
