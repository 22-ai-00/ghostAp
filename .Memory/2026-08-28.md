# 2026-08-28

## COT 合法 ACP 生命周期不再误降级到主卡

### 现象与根因

- 用户截图中的“过程展示已切换到主卡”对应 `logs.log` 在
  05:18:50 UTC 的 `reason=emit_rejected`，当时仅缓存了 9 个事件和
  716 bytes；不是 COT 容量、分段或 HTTP 超时。主卡继续运行是既有
  sidecar 降级设计，但这里的触发不应发生。
- 原生 COT 传输严格要求工具和推理的完整、不可重开的 AG-UI 生命周期；
  ACP 则合法允许 reconnect 后 `TOOL_CALL_UPDATE`/`TOOL_CALL_DONE` 先到，
  也允许 terminal-only progress。
- 适配器在 native COT 路径中绕过了主卡原有的缺失工具 START 补齐逻辑，
  因而严格映射拒绝该原子并触发 sidecar cutover。
- 另外，`THOUGHT → TEXT → THOUGHT` 会软关闭并复用同一 reasoning block
  ID；COT 将第二个 START 视为已关闭后的幂等空操作，随后拒绝 reasoning
  delta。部分 provider 还会在 terminal 后复用 raw tool-call ID，产生同类
  已完成工具生命周期冲突。

### 修复

- `src/card/programming_adapter.py`：在 native COT 路由中为缺失 START 的
  工具 UPDATE/DONE 合成完整开始帧，并以 COT-local active-tool ledger 防止
  重复合成；正常的失败/容量降级仍按原顺序回放至主卡。
- 同模块在 native COT 活跃时，正文插入后的 reasoning soft close 会 retire
  已关闭 block ID，使后续 thought 建立新的远端生命周期；非 COT 主卡行为
  保持不变。
- 所有 ACP 工具帧先映射为 invocation-scoped logical block ID。同一 raw ID
  在 terminal 后再次 START 会得到新 ID；未见 START 的首次 progress 仍会
  materialize，已关闭调用的迟到 UPDATE/DONE 则忽略，避免伪工具调用。
- `src/card/events/payloads.py` 与 `src/feishu/cot.py` 保留 raw tool ID 仅作
  私有 opaque metadata。COT 对工具名、参数、增量和结果都同时脱敏 logical
  与 raw ID，避免 logicalize 后把原始 provider 调用号写入飞书内容。

### 验证

- 真实 `FeishuCOTStream` + SDK recording client 回归覆盖：
  - `UPDATE → DONE` 缺失 START 时合成 `TOOL_CALL_START → ARGS → END → RESULT`，
    COT 持续健康且无主卡切换；
  - `THOUGHT → TEXT → THOUGHT` 生成两组完整、不同的 reasoning 生命周期；
  - raw 工具 ID 重用在无 COT 主卡中保留为两个独立工具，在 COT 中生成两组
    不同 remote toolCallId/结果且请求 JSON 不泄露 raw ID；
  - `START → DONE → DONE → UPDATE` 不产生幽灵结果或 cutover。
- 相关模块回归：`127 passed`；非慢全量：
  `4423 passed, 25 deselected, 43 subtests passed`。
- `uv run ruff check`（修改文件）、`uv run python -m src.main --validate`、
  `uv run python scripts/test_inventory.py tests/` 与 `git diff --check` 均通过。
  唯一 warning 是已记录的上游 `lark_channel` protobuf `utcfromtimestamp()`
  弃用提示（B054）。

### 后续风险

- 尚未在真实飞书租户复现同一 ACP 事件序列；本地回归使用真实 COT stream 和
  完整 wire 断言。部署后应观察 `emit_rejected` 是否归零或只剩真正异常帧。
- COT segment 已封存、但下一段启动或 anchor 重放失败时，当前 rollover 返回
  `sealed=False`，适配器可能将已封存段的 replay buffer 又投影到主卡；该
  partial-success 重复展示风险已登记为 B088，留待维护窗口处理。
