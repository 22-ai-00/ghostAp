# 2026-11-24 — Workflow 生产级 Teamwork 多工具协作与 `tool + model + effort` 优化

## 改动摘要（M1–M4）

1. **领域标识、能力发现与全链路 `effort` 透传（M1）**
   - `src/workflow_engine/tool_registry.py`：新增 `ToolCapability`、`get_tool_capabilities()` 与 `validate_agent_binding_spec()`，支持非阻塞读取工具/模型/Profile/Effort 能力并校验无效工具或不支持的 effort。
   - `src/workflow_engine/agent_pool.py`：扩展 `WorkflowAgentBinding` 支持 `role` / `roles`，`binding_key` 扩展为 `(tool_name, model_name, profile, effort)` 四元组以允许同 `tool + model` 搭配不同 `effort`/`profile` 共存；新增 `effective_model_name()` / `resolve_effective_model_name()` 经由 `src/acp/*_selection.py` 解析后端规范模型字符串。
   - `src/workflow_engine/{models,run_spec,journal,state_manager,engine,executor}.py` 与 `src/agent_session/{model_diagnostics,wrappers}.py`：端到端透传 `effort`/`profile`/`role`/`effective_model`，隔离不同 effort 的 Journal 缓存键与每绑定熔断器，并修复 DSH JSON-array failover 解析。

2. **Teamwork 多角色协作引擎与运行时流畅度（M2）**
   - `src/workflow_engine/teamwork.py`、`script_gen.py`：新增 `recommended` / `quick` / `collaborative` / `review_team` / `deep_collab` Teamwork 协作预设与角色亲和度映射，`generate_teamwork_script()` 确定性模板及多成员 fallback。
   - `src/workflow_engine/runtime/runtime.js`、`bridge.py`：移除 `fanout()` / `tournament()` 2000/1500 字符截断，支持 5 段式 handoff 无损汇总与独立 verifier 路由；对齐 schema 修复超时 `(1 + SCHEMA_RETRY_MAX)`；修复 `RuntimeBridge.start()` ready-timeout 子进程死锁。
   - `src/workflow_engine/progress_coalescer.py`、`errors.py`、`reporting.py`：新增 leading-edge 快速首刷（~10ms）、线性复杂度日志与路径脱敏、以及 HTML/MD 报告中的 `effort`/`profile`/`role` 展示。

3. **Card 2.0 配置构建器与渲染器可见性（M3）**
   - `src/card/builders/workflow.py`、`src/card/actions/dispatch.py`、`src/card/events/payloads.py`、`ux/workflow-team-config.html`、`ux/workflow-message-card.html`：新增纯 Card JSON 2.0 团队配置构建器与 `WF_CONFIG_ACTIONS`，并在 `ux/` 下保持对齐预览。
   - `src/workflow_engine/renderer*.py`、`result_brief.py`：在生成、进度、单卡执行与终态卡中展示 `effort`/`profile`/`role`，为生成卡增加停止按钮，并保留 `FAILED` 终态真实结论。

4. **飞书 `/wf` 交互闭环、持久化与缺陷修复（M4）**
   - `src/project/{context,manager,__init__}.py`：在 `ChatProjectState` 新增按 `(chat_id, root_path)` 严格隔离的 `workflow_team_config` 持久化、`commit_workflow_team_configuration()` 原子提交/回滚与损坏配置静默自愈。
   - `src/workflow_engine/commands.py`、`src/feishu/{product_catalog,action_registry,ws_client}.py`、`src/feishu/handlers/workflow_config.py`：接入 `/wf_config`（保留 23 命令面板契约）、`WF_CONFIG_ACTIONS` 同步 Card 2.0 `toast`+`card` 回调响应、`/wf`（无参配置 vs `--preset <id> <需求>` / `<需求>` 启动）及预设直通 fast-path。
   - 修复 5 项 E2E 阻塞缺陷及生命周期/渲染问题：补充 `source_script_path`、修复 `system.py` `/stop` 检测 `workflow_project.status`、修复 `diagnostics_helper.py` `PhaseProgress.finished_at` 完成数统计、`/wf_status` 原地更新活跃卡片防刷屏、透传 `chat_id`/`project_id` 至 `WorkflowGenerationRenderer`、`_without_stop_actions()` 裁剪 `behaviors[0].value`/空 `column`/`column_set` 及前置 `hr`、生成阶段 `ProgressCoalescer` 防抖、修复 `workflow_execution.py` 同步调度下的 `delivery_lock` AB-BA 死锁、COT `agent_started`/`agent_done` 展示 `effort`/`role`，以及 `progress_coalescer.py:43` 叶子锁注释对齐。
   - M4 复核加固（Iteration 2）：修复缓存失效重建配置会话时 `value["preset_id"]` 覆盖已保存团队、支持 Effort 工具（如 `traex`）无效 `profile` 绕过校验、`WF_SAVE_TEAM` 静默吞掉当前选中成员无效/冲突未保存编辑、以及 `GENERATING_SCRIPT` 阶段 `/wf_status` 回复 `"Workflow: idle"` 的 4 项缺陷；补齐 `_get_wf_config_state` 跨群/跨项目隔离、`WF_START_WORKFLOW`/`override_pool` 实时工具可用性校验、`/wf_help` 透传 `chat_id`/`project`，以及 `normalize_workflow_team_config()` 先校验后截断上限。
   - M4 复核加固（Iteration 3）：为复用 `WorkflowEngine` 新增 `clear_stale_renderer_for_generation()` 并在 `GENERATING_SCRIPT` 入口清理旧 `_renderer_wf`/`_state_manager`，同时在 `get_progress_cards()`、`get_status_text()` 与 `show_workflow_status()` 中确立 `GENERATING_SCRIPT` 严格优先级，防止二次运行 `/wf_status` 被 Run 1 旧渲染器劫持；在 `_ui_role()` 中补齐 `"verifier"` 防止将预设 `verifier` 成员静默降级为 `"worker"`；在 `_apply_config_transition()` 缓存未命中重建时，当回调携带渲染快照 `tool_name` 时同步重置缺失的 `model_name`/`profile`/`effort` 为 `None`，避免 `saved_cfg.members[0]` 的旧 `profile`/`effort` 跨成员或跨工具泄漏；并将 `workflow.py` `override_pool`/`saved_cfg` 校验的 `available_tools` 改为直接传入实时字典，避免空可用集回退陈旧缓存。
