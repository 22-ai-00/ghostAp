# 2026-08-27

## TraeX `/model` 完整目录恢复

### 现象与根因

- 用户截图中 TraeX 的模型下拉只剩一个 `TraeX active model`，但卡片顶部仍能
  显示当前真实模型，说明 provider 和会话状态正常，模型目录发生了退化。
- TraeX 会在 `new_session` 中同时暴露两套模型信息：旧 `models` 状态与
  `config_options[id=model]`。部分 adapter 版本只在旧状态中放一个当前模型
  哨兵，而完整 live 白名单仍位于 model config option。
- 共享 `_response_models()` 只要看到旧状态非空就提前返回，导致哨兵遮蔽完整
  config 目录。后续 Profile/Effort metadata 只会丰富 live 白名单，不会凭本地
  缓存猜测额外模型，因此卡片最终稳定退化为单项。
- TraeX 的真实启动和在线切模本来就通过 `session/set_config_option` 执行，目录
  却优先读取旧状态，发现权威与执行权威不一致。

### 修复

- `src/acp/helper.py` 对 TraeX 改为优先解析权威 model config option；只有该
  目录缺失时才兼容回退旧 `models` 状态。Codex、DSH 和其他 ACP provider 的
  发现顺序保持不变。
- 保留既有“adapter live 白名单 + 本机 metadata Profile/Effort”的交集契约，
  没有把本地缓存直接冒充在线可用目录，也没有新增后端特定静态模型表。
- `tests/test_acp_model_cache.py` 新增混合响应回归：旧状态只含
  `TraeX active model`，config option 同时含两个真实模型；断言最终只展示完整
  config 目录并正确保留默认模型。
